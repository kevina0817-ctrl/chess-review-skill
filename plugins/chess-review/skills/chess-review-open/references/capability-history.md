# 可量化的能力趋势

当用户要求总结优势、持续变化及训练方向时，不把单次好棋列表当作能力趋势。可在已授权的评分历史配置中增加 `capabilities`：

```json
{"username":"确认的账号","cache_dir":"评分档案缓存路径","capabilities":{"pool":"rapid","engine":"/absolute/path/to/verified-stockfish","cache_dir":"能力分析缓存路径"}}
```

默认只统计指定池最近60盘标准计分棋，包含胜和负。使用评分同步后的所有月度缓存，无需用户把未复盘的棋局重新贴出来。每次普通 `build_leaks.py` 在评分同步后更新能力统计；同一引擎二进制SHA256、分析版本、用户和PGN共享缓存，只计算新棋。引擎/规则变化会重新计算，不能混用口径。缓存应在本地忽略目录，不发布原始工作文件。

- 以三个连续、互不重叠的20盘窗口比较，不将零散成功次数视为长期成长。
- 有限分值的本人走法，评估下降≥200cp为一次明显失误。单线程、Hash64、40k nodes筛查，候选≥150cp以200k nodes复核。强制将杀评估不转换为兵值，排除对应分母。与旧单盘其他失误分类不直接相加。
- 一步将杀机会逐一枚举合法走法，实战直接将死算成功。
- 防杀机会只计本人未被将军、对手下一步存在将死、同时存在避免此将死的合法走法的局面；无需等待对手实战走出将杀。无法解救和多步杀不在此口径。
- 显示成功/机会数、涉及盘数，避免一盘里反复出现的机会被误认为跨局稳定能力。
- 分段显示前10回合、11–25回合、26回合以后；后段不自动称残局。
- UI 三组方向一致且首末变化达到门槛才描述连续改善，明确是观察性样本变化，不是显著性检验或已掌握技能。样本不足不归为优势。对手/局面难度未校正。
- 成长页优先呈现相对优势、量化趋势、下一步动作；旧 `progress` 数据保留用于兼容，但已启用能力趋势时移除原好棋列表DOM，不再作为页面内容。每盘复盘内的好棋教学点保留。
- 评分曲线继续独立展示全部可用评分池；能力统计明确标明自己分析的池，切换评分曲线不会冒充更新能力样本。
- 同步/分析失败保留上一份完整快照，并显示过期状态；不得生成新的进步结论或用部分已完成分析替换完整快照。

验证：测试精准将杀/防杀局面、统计分母、全部实战证据合法性；检查三阶段数值、缺少机会/样本不足/过期状态、旧好棋列表移除、桌面手机和离线；全量回归漏洞与既有复盘。

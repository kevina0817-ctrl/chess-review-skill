# 复盘数据格式

构建命令接收一盘规范化 PGN 和一个 UTF-8 JSON 文件。以下示例仅展示字段；基于新棋局重写文字和变化，不能套用某盘旧结论。

```json
{
  "archive_date": "2000-01-01",
  "timezone": "America/Toronto",
  "user_color": "white",
  "intro": "本盘最值得改进的是吃子前检查对方能否吃回。",
  "overview": ["根据本盘事实写整体判断。"],
  "strengths": ["列出具体下得好的回合，并解释原因。"],
  "training": [{"title": "先检查吃回", "text": "每次吃子前，找出对方能攻击落点的棋子。"}],
  "notes_prompt": "我当时看到了什么，漏掉了什么？",
  "review_guide": "导入 PGN 后，在关键步停下，独立想一手再比较。",
  "ending": "写准确的终局情况，不根据结果猜测认输、超时或将死。",
  "provenance": "按实际情况注明引擎及核对范围，或说明为人工分析。",
  "date_note": "解释归档日期与原棋谱日期。",
  "lessons": [{
    "ply": 14,
    "tag": "丢子",
    "title": "吃兵之前先检查对方的车",
    "summary": "一句话描述这个关键局面。",
    "why": "解释实战走法的问题与实际后果。",
    "fix": "用具体棋子和格子解释更好的走法。",
    "habit": "下一盘可以执行的一条检查习惯。",
    "hint": "不直接给完整答案的提示。",
    "actual_plies": 2,
    "better": ["Nc3"],
    "positive": false,
    "assert_mate": false,
    "accepted_moves": []
  }]
}
```

## 索引和分支

- `ply` 为教学局面之前已经完成的半回合数，起始局面是 `0`。普通起始位置：白方第 n 步之前为 `2*(n-1)`；黑方第 n 步之前为 `2*(n-1)+1`。
- 有自定义 FEN 时，从提供的起始局面计数，不能直接套普通公式；使用 `positions.json` 逐项确认。脚本从局面推导实际回合号和轮到哪一方。
- `actual_plies` 是展示多少个实际半回合，默认 4，超出棋谱尾部自动截断；不要自己伪造实战变化。
- `better` 是 SAN 着法数组，不带回合编号，例如 `["Rf8#"]`。所有变化从该 `ply` 的真实局面开始。
- `positive: true` 标识值得保留的好棋；此时示范可以与实战相同。
- `assert_mate: true` 要求改进分支的最后局面确为将死。不填写不代表允许文字里未经验证地声称将死。
- `accepted_moves` 可列已核对的其他合理首着，例如 `[{"san":"...","feedback":"为什么这手也合理。"}]`。默认只认可主示范，其他走法反馈为“合法但不是本页示范”，不会自动判为错误。
- 所有文章字段是纯文本，由构建器转义。每个段落数组元素显示为一个段落。
- `date_note`、`provenance` 和 `ending` 必须与实际证据一致。网页不默认声称已使用 Stockfish，也不会从 1-0 推断对手认输。
- 不需要填写名字、等级分、用时或原对局 URL；这些从 PGN 获取。缺少的等级分不显示；URL 仅允许 HTTP(S)。不要为填满界面而编造数据。

## 文件冲突

正常命名为归档日期加对手。生成到空的暂存目录，验证后交付。如果目标目录已有另一盘同日同对手的对局，在核对后给复盘 JSON 增加 `"filename_suffix": "02"`，即可让本次 HTML、PGN 和网页下载文件名一起增加 `_02` 后缀。用户明确要修改现有网页时，可在暂存区完成并验证后替换指定文件。
